# Прокси-туннель для OpenWrt

Shell-скрипт подключает OpenWrt к прокси-серверу через
[sing-box](https://github.com/SagerNet/sing-box) и даёт простую веб-панель для
выбора сервера и маршрутизации по списку доменов.

## Возможности

- несколько ссылок серверов или HTTP(S)-подписка;
- VLESS, VMess, Trojan, Shadowsocks, Hysteria2 и TUIC;
- все поддерживаемые серверы из подписки с сохранением выбранного;
- автоматический URLTest-failover внутри sing-box; ручное переключение без
  перезапуска при наличии `curl`, иначе с безопасным restart;
- адаптивная веб-панель с флагами, типами подключения, пингом и индикатором
  качества, без Node.js, Python и базы данных;
- фильтр серверов по протоколу;
- ручное обновление подписки без фоновых загрузок;
- обновление скрипта, `sing-box` и включённых списков из веб-панели;
- два режима: весь внешний трафик через прокси или только домены из списка;
- переключатели Re:filter и заблокированных IP РФ;
- переключатель маршрутизации официальных сетей Telegram через прокси;
- прозрачный TCP/UDP-прокси через TPROXY;
- локальные SOCKS5- и HTTP-прокси;
- сервис procd с восстановлением процесса, firewall-hook и резервным watchdog;
- `sing-box` 1.13.12 с официальными Linux-сборками для OpenWrt.

Тип подключения определяется по схеме ссылки, а транспорт и TLS-параметры —
по её содержимому. Для VLESS, VMess и Trojan поддерживаются TCP, WebSocket и
gRPC. VLESS работает без TLS, с TLS и REALITY. Hysteria2 поддерживает
стандартную ссылку `hysteria2://` или `hy2://` и obfs `salamander`.
Shadowsocks поддерживается без SIP003-плагинов.

## Установка

С подпиской:

```sh
wget --no-check-certificate -qO- \
  'https://raw.githubusercontent.com/Alex12571333/xray-openwrt/main/xray-setup.sh' \
  | sh -s -- 'https://example.com/subscription'
```

С готовой ссылкой сервера:

```sh
wget --no-check-certificate -qO- \
  'https://raw.githubusercontent.com/Alex12571333/xray-openwrt/main/xray-setup.sh' \
  | sh -s -- 'vless://UUID@SERVER:PORT?...'
```

Скрипт установит `sing-box`, при необходимости установит `uhttpd`, применит
конфигурацию и напечатает адрес панели. Для входа используется логин `root` и
пароль root от роутера. Если пароль ещё не задан:

```sh
passwd
sh /etc/sing-box/setup.sh panel-start
```

## Веб-панель

Если на роутере есть сертификат `/etc/uhttpd.crt` и ключ `/etc/uhttpd.key`,
панель слушает только LAN-адрес:

```text
https://192.168.1.1:8088/cgi-bin/panel
```

Самоподписанный сертификат может вызвать предупреждение браузера. Если HTTPS
недоступен, панель слушает только `127.0.0.1`. Откройте SSH-туннель:

```sh
ssh -L 8088:127.0.0.1:8088 root@192.168.1.1
```

Затем откройте:

```text
http://127.0.0.1:8088/cgi-bin/panel
```

Точный текущий адрес показывает команда:

```sh
sh /etc/sing-box/setup.sh status
```

Панель защищена Basic Auth и CSRF-токеном. Полные ссылки, пароли и UUID в
интерфейсе не показываются.

## Серверы

В панель можно вставить одну или несколько ссылок — по одной на строку.
Одинаковые ссылки удаляются. Подписка загружается целиком и оставляет только
поддерживаемые типы. Серверы показываются по имени из фрагмента `#Name`, адресу
и типу подключения. При обновлении подписки выбранный сервер сохраняется, пока
он остаётся в подписке. Изменение только имени после `#` не сбрасывает выбор;
если сам сервер исчез, выбирается первый.

В ручном режиме активен выбранный сервер. В автоматическом режиме URLTest раз
в минуту проверяет все серверы и переводит новые соединения на доступный.
Кнопка «Пинг» отдельно проверяет ICMP-задержку первых 30 серверов и сохраняет
результат до следующей проверки или смены источника. Если сервер блокирует
ICMP, панель покажет таймаут, хотя сам прокси может работать.

Подписка обновляется только вручную кнопкой возле списка серверов или командой
`refresh`. Новая конфигурация сначала проходит `sing-box check`; для активного
или запускаемого туннеля дополнительно проверяется реальное соединение. При
ошибке восстанавливаются предыдущие настройки и выполняется попытка вернуть
рабочее подключение. Остановленный туннель при редактировании источника,
сервера или маршрутов не запускается сам.

## Маршрутизация

| Режим | Через прокси | Напрямую |
|---|---|---|
| Весь трафик | публичный IPv4 и активный IPv6 | приватные и служебные сети |
| Только список | свои домены, включённые внешние списки и Telegram | остальной трафик |

В режиме списка `sing-box` распознаёт домен по HTTP Host, TLS SNI и QUIC SNI.
Соединения без видимого имени узла идут напрямую, если адрес не входит во
включённый IP ruleset. При использовании ECH домен также может быть недоступен
для распознавания.

Можно вставлять домены, URL и маски вида `*.example.com`: панель сохранит
нормализованный домен `example.com`. Поддерживаются ASCII-домены и Punycode.

Переключатель «Обход звонков Telegram» направляет официальные IPv4-сети
Telegram через прокси. Чтобы звонок гарантированно использовал relay Telegram,
отключите P2P для звонков в настройках самого приложения.

Переключатель Re:filter использует локальные доменный и IP ruleset из
[1andrevich/Re-filter-lists](https://github.com/1andrevich/Re-filter-lists).
«Заблокированные IP РФ» включает основной и community ruleset из
[runetfreedom/russia-blocked-geoip](https://github.com/runetfreedom/russia-blocked-geoip).
Все включённые категории добавляются друг к другу и ведут в один outbound
`proxy`; они не заменяют свои домены или Telegram. Файлы скачиваются при первом
включении и затем только вручную общей кнопкой «Обновить».

LAN-интерфейсы берутся из UCI, с безопасным fallback на `br-lan`. IPv4
настраивается всегда, IPv6 — при наличии активного IPv6 default route. После
перезапуска firewall TPROXY восстанавливается через UCI include без ожидания
cron.

## Порты

| Порт | Назначение |
|---|---|
| `1080` | SOCKS5-прокси |
| `1081` | HTTP-прокси |
| `1082` | локальная HTTP-проверка здоровья |
| `12345` | IPv4 TPROXY для клиентов LAN |
| `12346` | IPv6 TPROXY для клиентов LAN |
| `9090` | Clash API только на localhost для переключения сервера |
| `8088` | веб-панель: HTTPS на LAN или HTTP только на localhost |

Порты `1080`, `1081` и `12345` слушают IPv4, `12346` — IPv6. Порты `1082` и
`9090` доступны только с самого роутера. Ограничьте доступ к прокси-портам
правилами firewall роутера.

## Управление

```sh
sh /etc/sing-box/setup.sh
sh /etc/sing-box/setup.sh status
sh /etc/sing-box/setup.sh restart
sh /etc/sing-box/setup.sh refresh
sh /etc/sing-box/setup.sh stop
sh /etc/sing-box/setup.sh servers
sh /etc/sing-box/setup.sh routing
sh /etc/sing-box/setup.sh panel-start
sh /etc/sing-box/setup.sh self-update
sh /etc/sing-box/setup.sh test
```

`stop` отключает туннель, но оставляет панель доступной. Запуск из панели или
команда `restart` снова включают туннель.

## Проверка

```sh
iptables -t mangle -L SBOX_TP -n -v
curl --socks5-hostname 127.0.0.1:1080 https://api.ipify.org
tail -f /var/log/sing-box.log
```

Перед заменой активной конфигурации выполняется `sing-box check`, после запуска
проверяется HTTP-доступ через локальный proxy. Последний подтверждённый конфиг
и предыдущий бинарник сохраняются для автоматического rollback. Аварийное
завершение процесса восстанавливает procd; команда `stop` удаляет TPROXY и
возвращает трафик напрямую.

## Файлы на роутере

| Путь | Назначение |
|---|---|
| `/usr/bin/sing-box` | исполняемый файл |
| `/etc/sing-box/config.json` | активная конфигурация |
| `/etc/sing-box/config.good.json` | последняя проверенная конфигурация |
| `/etc/sing-box/servers` | серверы из текущего источника |
| `/etc/sing-box/vless_url` | выбранная ссылка сервера |
| `/etc/sing-box/sub_url` | URL подписки |
| `/etc/sing-box/route_mode` | режим `all` или `list` |
| `/etc/sing-box/proxy_domains` | нормализованный список доменов |
| `/etc/sing-box/telegram_calls` | состояние обхода звонков Telegram |
| `/etc/sing-box/refilter_enabled` | состояние Re:filter |
| `/etc/sing-box/russia_blocked_enabled` | состояние списка заблокированных IP РФ |
| `/etc/sing-box/rules/*.srs` | локальные внешние ruleset-файлы |
| `/etc/sing-box/ping_cache` | последний результат проверки задержки |
| `/etc/sing-box/auto_select` | включён автоматический URLTest-failover |
| `/etc/sing-box/disabled` | туннель остановлен пользователем |
| `/etc/sing-box/setup.sh` | установленная копия скрипта |
| `/etc/init.d/sing-box-tunnel` | сервис procd |
| `/etc/sing-box/firewall.include` | восстановление TPROXY после reload firewall |
| `/var/log/sing-box.log` | журнал sing-box |
| `/var/log/sing-box-panel.log` | журнал панели |

## Требования

- OpenWrt с `opkg` или `apk`; ARM64-профиль проверен на OpenWrt 21.02.7;
- пароль пользователя `root`;
- ядро и firewall с поддержкой TPROXY;
- `tar`, `grep`, `sed`, `awk`, `find`, `mktemp`;
- `curl`, `uclient-fetch` или `wget`;
- штатный `jsonfilter` OpenWrt для VMess.

Если отсутствуют `base64`, полный `ip`, `iptables`/TPROXY или `ip6tables`,
скрипт устанавливает необходимые пакеты через системный менеджер OpenWrt.

Поддерживаемые архитектуры: `aarch64`, `armv7l`, `armv6l`, `x86_64`,
`i686`, `i386`, `mips` и `mipsel`.
